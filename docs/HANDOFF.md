# 給 Haley 的交接文件

這份文件是寫給 Haley 看的——你是新娘的妹妹，之後由你負責維護這個網站跟後面的試算表。你是設計師、不是工程師，這份文件會用白話帶你完成「開通」跟「換成真實資料」，不需要懂寫程式。照著順序做就好，每一步都有寫清楚要點哪裡。

---

## 1. 這是什麼

這是新娘與新郎的婚禮邀請函網站（線上喜帖），網址開起來上半是邀請函、下半是「出席意願表單」，賓客填完按送出，資料會自動寫進一份 Google 試算表。網站本身不用另外裝主機、不用另外寫後端，全部是免費的：網站放在 GitHub Pages，表單資料的接收放在你（Haley）自己的 Google Apps Script（Google 帳號內建、免費）。

## 2. 接收 repo 後第一次要做的事

這個 repo（程式碼倉庫）會用 GitHub 的「Transfer repository」功能，從 Chian 的帳號 `chi-an-yang` 轉移到你的 GitHub 帳號。轉移信寄到你信箱之後，照下面順序做：

1. **接受轉移信**：信箱裡會收到一封 GitHub 的 repository transfer 邀請信，點裡面的連結接受。接受後 repo 會出現在你自己的帳號底下，網址會變成：
   ```
   https://github.com/<你的 GitHub 帳號>/wedding-invite
   ```

2. **確認 GitHub Pages 有開**：進 repo → 上方 `Settings` → 左邊選單 `Pages`。確認「Build and deployment」→「Source」是選 **GitHub Actions**（不是 "Deploy from a branch"）。轉移 repo 之後 Pages 設定有時候會被重置成沒開，如果看到是空的或選到別的選項，重新選一次「GitHub Actions」存檔。

3. **建立你自己的試算表與 Apps Script**：這一步 Chian 會親自帶你做一次，完整步驟寫在 [`apps-script/README.md`](../apps-script/README.md)。做完你會拿到一個網址（結尾通常是 `/exec`），先複製起來，下一步要用。

4. **把 Apps Script 網址存進 GitHub Secrets**：進 repo → `Settings` → 左邊選單 `Secrets and variables` → `Actions` → 按 `New repository secret`。
   - Name 填：`VITE_RSVP_ENDPOINT`
   - Secret 貼上第 3 步拿到的 Apps Script 網址
   - 按 `Add secret`

5. **手動跑一次部署**：進 repo 上方 `Actions` 分頁 → 左邊選 `Deploy to GitHub Pages` → 右邊 `Run workflow` → 選 `main` 分支 → 按綠色 `Run workflow` 按鈕。等它跑完（畫面上的圈圈變成綠色勾勾，大約 1-2 分鐘）。

6. **開網址測試**：跑完之後打開：
   ```
   https://<你的 GitHub 帳號>.github.io/wedding-invite/
   ```
   把下半的表單隨便填一筆送出（可以填「測試」當姓名），確認畫面出現「已收到您的回覆」。

7. **回試算表確認收到**：打開你在第 3 步建的試算表，「工作表1」應該多一列剛剛那筆測試資料。

8. **刪掉測試列**：確認有收到之後，回試算表把那筆測試資料整列刪掉，保持資料乾淨。

做完這 8 步，開通就完成了，之後賓客填表都會正常寫進你的試算表。

## 5. 日常怎麼看回覆

你的試算表裡有兩個工作表：

- **工作表1**：賓客每填一次表單就多一列，是最原始、最完整的資料，什麼都看得到（姓名、關係、出席狀態、人數、飲食、電話、地址、祝福留言……）。
- **統計**：這個工作表是自動算好的整理結果，分四個區塊，不用自己動手算：
  - **A:C 欄**：統計數字（出席組數、出席總人數、各種飲食需求人數、兒童椅／餐具總張數）
  - **E:G 欄**：喜餅要郵寄的名單（姓名／電話／地址）
  - **I:P 欄**：確定出席的完整名單（姓名、關係、人數、飲食、兒童椅餐具、電話、備註）
  - **R:V 欄**：禮到人不到或無法出席的名單

這個「統計」工作表的數字跟名單會**自動即時更新**，賓客一填表，這裡就會跟著變，不用手動重新整理或重跑任何東西。

## 6. 注意事項

- **改了 `Code.gs` 一定要重新部署才會生效**：如果以後你（或請人）去動 Apps Script 裡的程式碼（`Code.gs`），光按存檔（Ctrl+S）不會讓網址背後的程式真的更新，一定要到 Apps Script 編輯器右上角「部署」→「管理部署作業」→ 點鉛筆圖示編輯 → 版本選「新版本」→ 按「部署」，這樣改動才會生效。這是 Apps Script 最容易踩的坑，忘記做的話會覺得「我明明改了怎麼沒反應」。
- **這個 repo 是公開的（public）**：換成真實資料上線之後，新人姓名、地址、電話這些內容任何人都看得到網頁原始碼或直接打開網站看到（本來紙本喜帖上的資訊也是公開給收到的人看，性質類似，但這裡是放在網路上，任何知道網址的人都能看到，先讓你知道一下）。
- **不要動 `.github/workflows/deploy.yml`**：這個檔案是自動部署網站用的設定，不需要碰它，改了有可能讓網站部署失敗。
